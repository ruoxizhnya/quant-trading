## 1. 一句话定义

> **一个 AI 投研研究员平台：既能在全市场横向筛选（N 股 × 1 因子，日频，出信号），也能对单只股票纵向深挖（1 股 × N 季度，季度频，出研究档案），并且两者共享同一份数据、同一套证据链、同一组质量门禁。**

它由两个工作面 + 一个共享底座构成：

```
        ┌──────────────────────┐   ┌──────────────────────┐
        │  工作面 1：纵向深研    │   │  工作面 2：横截面选股  │
        │  "这家公司发生了什么"  │   │  "市场在定价什么"      │
        │  1 股 × N 季度        │   │  N 股 × 1 因子        │
        │  产出：研究档案        │   │  产出：交易信号        │
        └──────────┬───────────┘   └──────────┬───────────┘
                   │     飞轮闭环 ①↔②↔③↔④      │
                   └───────────┬───────────────
                               ▼
        ┌──────────────────────────────────────────────────┐
        │  共享底座：唯一数据面 + 统一计算面 + 统一编排面      │
        │  （原 Quant Lab 的全部能力降维为此底座）            │
        └──────────────────────────────────────────────────┘
```

## 2. 产品定位

**是什么**：一个自托管（self-hosted）的 AI 驱动投研平台，面向有经验的个人投资者与小型投研团队。

**它和市面上的东西有什么不同**：

| 现有工具的形态 | 本产品的形态 |
|---|---|
| 横截面选股工具（聚宽/米筐/Wind）：能筛全市场，但不知道单家公司发生了什么 | 横截面 + 纵向，两侧互相驱动 |
| 基本面研究工具（Wind/Choice/Excel）：能看财报，但研究结论无法被验证、无法沉淀、无法复用 | 研究结论可转化为因子、可被回测检验、可复利沉淀 |
| 两套系统拼在一起：数据两份、口径两套、结论对不上 | **一套数据面、一套证据链、一套质量门禁** |

**为谁**：想要"证据而非直觉"的个人投资者；需要沉淀研究方法的独立研究者。

**核心承诺（三个硬承诺，跨两个工作面统一适用）**：

1. **数字可信** — 每一个出现在报告或信号里的数字，都能回溯到唯一一条原始记录（内容哈希锚定），而非"我记得是这个数"。
2. **研究复利** — 研究产出不是一次性报告，而是可累积、可被 agent 读取、可被回测检验的结构化资产。
3. **观点分层** — 事实 / 推断 / 存疑三层严格区分，任何未经证据锚定的论断不得进入下游。

## 3. 两个工作面

两个工作面是**对等的**（不是主从关系），共享下方的 L0-L2 三层。

### 3.1 工作面 1：纵向深研（EquityDeep）

| 维度 | 说明 |
|---|---|
| 研究单位 | 1 只股票 × N 个季度 |
| 时间尺度 | 季度频（财报期驱动） |
| 产出 | 研究档案（`_profile.md`）：结论 / 疑点 / 逐数溯源锚点 |
| 消费者 | 人（1 小时审读）+ Hermes Agent（作为研究上下文） |
| 形态 | Python research worker（容器化）+ Obsidian Vault 工作面 |

### 3.2 工作面 2：横截面选股（原 Quant Lab 能力）

| 维度 | 说明 |
|---|---|
| 研究单位 | N 只股票 × 1 因子 |
| 时间尺度 | 日频 / 分钟频 |
| 产出 | 交易信号 / 策略排序 / IC 与回测报告 |
| 消费者 | 回测引擎 / Hermes Agent（自主因子挖掘） |
| 形态 | Go 微服务 + Vue SPA |

### 3.3 对等性的含义（本期的产品选择）

横截面能力**不是**纵向能力的附属品或过渡态，而是并列的第二工作面，**本期纳入规划**。具体含义：

- 两个工作面共用 L0 数据面与 L1 计算面，但**各自有独立的编排（L2）与体验（L3）**；
- 横截面工作面的现有实现（Go 微服务 + Vue SPA）**保留**，不因纵向工作面的引入而降级；
- 底座改造（单一摄取入口、Evidence API、统一证据坐标）**同时服务两个工作面** —— 这是"有机融合"而非"新加一层"的判据。

## 4. 飞轮：为什么这是一个产品而不是两个工具

判断"一个产品"还是"两个工具堆叠"，标准是：**它们之间是否存在闭环的数据/价值流动**。本产品的答案是存在 —— 四步闭环：

```
              ┌────────────────────────────────────────────────
              │                                                │
              ▼                                                │
    ①  纵向深挖（工作面 1）                                      │
        研究 1 家公司 N 个季度 → 产出结论与疑点                    │
        例：茅台「合同负债 / 营业总收入 长期 > 30%」                │
              │                                                │
              │  结论被表述为「可检验的假设」                       │
              ▼                                                │
    ②  横截面验证（工作面 2）                                    │
        假设 → 因子表达式 → 全市场回测 → IC / 分组收益 / Sharpe     │
        例：`contract_liability_ratio` 进 factor_cache           │
              │                                                │
              │  结果回流                                       │
              ▼                                                │
    ③  理解修正（工作面 1）                                      │
        回测显示"无 alpha" → 反过来质疑原结论 → 更新疑点状态         │
        例：该比值在白酒板块外无区分度 → 结论限定适用域               │
              │                                                │
              │  异常触发                                       │
              ▼                                                │
    ④  触发深挖（工作面 1）                                      │
        策略在某板块异常好 → 深挖该板块标的 → 回到 ①                │
              │                                                │
              ────────────────────────────────────────────────┘
```

**每一圈飞轮，两侧资产同时增值**：

| 圈次 | 工作面 1 收益 | 工作面 2 收益 |
|---|---|---|
| ①→② | 结论被检验，不再是"自说自话" | 质量因子从"`ROE > 15%`"升级为可解释的多维因子 |
| ②→③ | 获得证伪信号，研究更诚实 | 因子适用域被精确标注（避免误用） |
| ③→④ | 深挖目标由数据驱动，非拍脑袋 | 策略异常获得因果解释（补 L5 人工审查缺口） |

**没有这个飞轮，产品就退化为两个独立工具**；有了它，产品的护城河是**积累起来的研究资产**（档案 + 因子 + 两者的对应关系），而非任何单点技术。

## 5. 四层架构

```
┌─────────────────────────────────────────────────────────────────────┐
│ L3  体验面 (Experience)                                              │
│   ├─ Obsidian Vault     纵向工作面：研究叙事的事实源（人 + agent 共写）│
│   ├─ Vue SPA            横截面工作面：回测 / 因子 / 策略 / 风控        │
│   └─ Hermes Agent       自然语言编排：驱动两个工作面                   │
├─────────────────────────────────────────────────────────────────────┤
│ L2  编排面 (Orchestration)                                           │
│   ├─ Research Pipeline  纵向：7-stage 深度研究流水线（EquityDeep）     │
│   ├─ Research Engine    横截面：因子挖掘 / 回测 / 演化 / 漂移检测       │
│   └─ MCP Tool Bridge    统一 agent 入口（18+ 内置工具，可发现）        │
├─────────────────────────────────────────────────────────────────────┤
│ L1  计算面 (Compute)                                                 │
│   ├─ 因子引擎           FactorComputer + Expression DSL + 基因池      │
│   ├─ 回测引擎           T+1 / 涨跌停 / 前复权 / WalkForward / Batch    │
│   ├─ 验证门禁           L1-L5（编译 / IC / 回测 / 走查 / 人工）        │
│   └─ 风控 · 执行        in-process（ODR-021）                         │
├─────────────────────────────────────────────────────────────────────┤
│ L0  数据面 (Data Foundation)  ← 唯一事实源 · 唯一摄取入口              │
│   ├─ ingest.raw      原始源响应（content_hash 唯一）← Evidence API 落点│
│   ├─ market.*        规范化行情 / 财务（可重建）                       │
│   ├─ quant.*         因子 / 回测 / IC（可重建）                        │
│   ├─ research.*      研究结构化状态（不可重建；vault markdown 的投影）  │
│   └─ Evidence API    GET /api/evidence/{content_hash} → 唯一原始记录   │
─────────────────────────────────────────────────────────────────────┘
```

**架构原则（沿用并强化 ODR-046 的五条）**：

1. **L0 是唯一数据面** —— 任何工作面、任何 agent、任何外部脚本，取数一律经 L0，不得自建数据副本。
2. **单一写者** —— 每个数据集只有一个写者：`ingest.raw`/`market`/`quant` 由 Go 后端写；`research.*` 由纵向工作面写；vault markdown 由人 + 纵向工作面写。
3. **单向依赖** —— L3 → L2 → L1 → L0，禁止反向依赖（计算面不得直接读 vault 文件）。
4. **可重建性** —— `market`/`quant`/`research` 三类结构化数据均标注"可否重建"；可重建者随时可 DROP 重建，不可重建者必须备份。
5. **契约优先** —— 跨层跨语言交互只通过显式契约（JSON Schema + 字段字典 + Evidence API），不读对方内部结构。

## 6. 数据归属：如何做到"不重复存储"

这是本方案的技术核心。做法不是"约定不要存两份"，而是**按数据性质分区，让每一类数据物理上只有一个权威位置**。

### 6.1 数据分类与归属

| 类别 | 内容 | 可重建？ | 唯一权威位置 | 其他侧是否留副本 |
|---|---|---|---|---|
| **A. 原始源响应** | tushare / akshare 返回的原始 payload（含中文原始字段名） | 可（重抓） | PG `ingest.raw`（`content_hash` 唯一键） | ❌ 无。仅持有 `content_hash` |
| **B. 规范化数据** | OHLCV、财报字段、交易日历、公司行为 | 可（从 A 重算） | PG `market.*` | ❌ 无。经只读证据 API 访问 |
| **C. 派生计算结果** | 因子值、回测结果、IC、分组收益 | 可（从 B 重算） | PG `quant.*` + Redis `factor_cache` |  无。经只读计算 API 访问 |
| **D. 研究叙事** | 结论 / 疑点 / 推断的**自然语言正文** | **不可**（人的判断） | **Vault markdown**（事实源） | — 本身即事实源 |
| **E. 研究结构化状态** | 结论/疑点的结构化字段（id、置信度、status、as_of、citations） | 可（从 D 确定性投影） | PG `research.*`（**投影，非权威**） | 权威在 D；`research.*` 可 DROP 重建 |

### 6.2 为什么这不叫"重复存储"

"重复存储"的判据是：**同一份数据存在两个都可写的位置，导致口径漂移**。本方案逐条规避：

- **A / B / C（可重建数据）**：物理上只存在于 PG 一处。纵向工作面**零副本**，运行期通过只读 API 取数。它不"同步一份到本地"，而是"每次按需读取"。
- **D（叙事）**：只存在于 vault markdown。它不在 PG 里存正文副本。
- **E（结构化状态）**：PG 里存的是 markdown 的**确定性投影**，性质等同于"索引/物化视图"：
  - 单一写者：由 `equitydeep sync`（确定性脚本，非 LLM）生成；
  - 冲突裁决：**以 markdown 为准**，投影与事实源不一致时重建投影；
  - 可丢弃：`DROP SCHEMA research CASCADE` 后可由 markdown 全量重建，无信息损失。
  - 存在的唯一理由是**跨层查询**（"哪些标的的疑点已转化为因子"需要 SQL join，无法在 markdown 上做）。

> **一句话**：可重建的数据物理唯一（PG）；不可重建的判断物理唯一（markdown）；两者之间只有"可重建投影"，没有"双写"。

### 6.3 证据快照的归属（对 EquityDeep 现有设计的修改）

EquityDeep 当前把 `snapshots/*.json`（原始源响应）存在 vault 内。在统一数据面下，**原始源响应的唯一权威位置改为 PG `ingest.raw`**：

| 项 | 原设计（EquityDeep 独立） | 新设计（统一数据面） |
|---|---|---|
| 原始 JSON 存放 | `vault/{ticker}/snapshots/*.json` | PG `ingest.raw`（唯一） |
| 溯源锚点 | 文件相对路径 `snapshots/20251120_income.json#/data/合同负债` | 内容坐标 `{content_hash, pointer}` |
| 反查方式 | 本地文件读取 | `GET /api/evidence/{content_hash}` |
| 离线核验 | 天然可离线 | `equitydeep evidence <hash> [--cache]`（显式 LRU 缓存，非事实源） |

**收益**：同一份财报被多个标的/多个工作面引用时，只存一次；跨源对账（tushare vs akshare）可在同一张表内完成；证据不再随 vault 目录迁移而失效。

## 7. 证据服务：平台级溯源能力

统一数据面的直接产物是一个**平台级能力**，而非某一个工作面的内部实现：

```
                        研究叙事中的每个数字
                                │
                                ▼
              citation = { source, dataset, key, as_of, content_hash }
                                │
                                ▼
              GET /api/evidence/{content_hash}
                                │
                                ▼
                    ingest.raw 中的唯一原始记录
                    （原始 payload + 摄取元数据 + 不可变）
```

| 能力 | 说明 |
|---|---|
| **不可变** | `content_hash` 是对原始 payload 的内容哈希；同一内容永远同一坐标 |
| **跨层可引用** | 报告脚注、因子定义、回测日志可用同一坐标引用同一数字 |
| **可审计** | 任意数字 → 任意时间点 → 任意源，全链路可复现 |
| **防幻觉** | 回查脚本对**声明**（citation 元组）做精确校验，而非对文本做子串猜测 |

> 这同时修复了 ODR-047 发现的 P0 缺陷（回查脚本全局子串匹配 → 假阳性）：因为证据从"文件路径 + 模糊字符串"升级为"内容坐标 + JSON Pointer 精确解析"，校验对象从"文本"变为"声明"。

## 8. 工作面 1（EquityDeep）的形态变更

用户已确认：EquityDeep **可以有 DB、可以有 Docker**。变更如下（**不重复存储**是硬约束）：

| 项 | 变更前 | 变更后 | 理由 |
|---|---|---|---|
| **DB** | 无（"文件系统即数据库"） | **接入共享 PostgreSQL 的 `research` schema**，不新建独立实例 | 复用同一实例的备份/迁移/连接池；避免第二个数据孤岛 |
| **Docker** | 无 | 作为 `equitydeep-research` worker 容器加入 docker-compose，与后端同网络 | 统一部署与运维；不再是"裸 CLI" |
| **取数** | 自行调用 akshare | **严格单一入口**：经 L0 只读证据 API 取数；akshare adapter 归入 Quant Lab 数据服务 | 避免同一份数据两处摄取（用户约束） |
| **原始快照** | vault 内 `snapshots/*.json` | 迁至 PG `ingest.raw`，vault 只留 `content_hash` 坐标 | 消除唯一的真实重复点（见 §6.3） |
| **叙事** | `_profile.md` | **不变** —— 仍为事实源，Obsidian 仍为工作面 | 用户已确认（Vault markdown 为唯一事实源） |
| **结构化状态** | `_profile.json` 镜像文件 | 升级为 PG `research.*` 投影（`_profile.json` 可保留为导出格式） | 支持跨层 SQL 查询 |
| **保留不变** | Python 3.11、7-stage 固定流程、逐数溯源、三硬承诺、非目标红线 | 同左 | 这些是 EquityDeep 的产品价值本体，不因形态变更而改变 |

## 9. 边界与红线

| 边界 | 内容 |
|---|---|
| ❌ **纵向工作面永久不产出** | 交易建议、目标价、评级（跨工作面红线，非仅内部约束） |
| ❌ **档案不是信号源** | 档案的合法用途仅两种：**因子假设来源** 与 **人工审查材料**。绝不把 `_profile.md` 的结论直接当策略信号 |
| ❌ **不做实时** | 纵向工作面按财报期驱动（季度频），不接实时行情、不做盘中监控 |
| ❌ **单一摄取入口不可绕过** | 任何组件不得直连外部数据源；新增数据源 = 在 L0 增加 adapter |
| ✅ **数据主权** | vault 与 PG 全部自托管，不上传第三方（VISION Principle 6） |
| ✅ **免责声明** | 报告与信号显著位置标注"不构成任何投资建议" |

## 10. 成功指标

| 指标 | 目标 | 测量 |
|---|---|---|
| **飞轮转数** | ≥ 3 个纵向结论转化为横截面因子并完成 IC 评估 | `factor_genes` 记录 + 档案 citation 对应 |
| **证据完整性** | 报告与信号中 100% 数字可用 `content_hash` 回溯到唯一原始记录 | 回查脚本（字段级锚定） |
| **数据无重复** | 同一原始 payload 在系统中仅存一份（`ingest.raw` 唯一键命中） | `content_hash` 去重统计 |
| **投影可重建** | `research.*` 可由 vault markdown 全量重建且无信息损失 | 重建演练 |
| **质量门禁覆盖** | 全部数据源（tushare / akshare）通过 10 票 × 20 数字抽检，错误率 < 2% | 抽检报告 |
| **档案被引用** | Hermes 会话中档案工具调用成功率 ≥ 95%（有档案时） | MCP 工具日志 |

## 11. 执行路线

> 原则：**先定义顶层，再分步执行**。每一阶段结束时产品都处于"可用且自洽"的状态。

| 阶段 | 名称 | 内容 | 出口判据 |
|---|---|---|---|
| **P0** | 顶层定义 | `PRODUCT.md`（本文件）+ `ADR-022`（统一研究平台，supersede ADR-021）+ `ODR-048`（重构记录） | 顶层文档体系自洽，后续阶段无定位歧义 |
| **P1** | 底座契约 | 单一摄取入口收敛 + `ingest.raw` + Evidence API + 契约冻结（`contracts/`）+ `research` schema DDL + 抽检脚本泛化 | 任意外部组件可经 Evidence API 拿到唯一原始记录 |
| **P2** | 工作面 1 跑通 | EquityDeep 接入 `research` schema + 容器化 + 改走 Evidence API 取数 + 回查脚本字段级锚定修复 → 通过 M1 质量门禁 | M1 通过（10 票 × 20 数字，错误率 < 2%）+ 快照零本地副本 |
| **P3** | 计算面补齐 | `fundamentals_detail` + 5 个纵向因子 + PIT（`ann_date <= D`） | 纵向结论可转为因子并计算 |
| **P4** | 飞轮打通 | 疑点 → 假设 → 因子 → 回测 → 结果回流档案（桥 B1 + B2 完整闭环） | 至少 1 圈飞轮端到端可复现 |
| **P5** | 横截面工作面 v2 | 现有横截面能力对齐新架构（统一证据坐标 + 单一摄取入口） | 两个工作面共享 L0-L2，无平行数据路径 |

**关键判断**：P0 → P1 是唯一真正的关键路径；P2 与 P3 可在契约冻结后并行；P5 是存量对齐，不阻塞飞轮验证。
